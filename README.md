# 단단상회 주문/상품 사이트 — 시작 가이드

Next.js(App Router) + Google Sheets(상품 DB) + Cloudinary(이미지) 조합입니다.
전부 무료 플랜으로 운영 가능합니다.

## 폴더 구조

```
dandan-shop/
├─ app/
│  ├─ page.jsx                 메인: 날짜탭 + 상품 목록
│  ├─ layout.jsx
│  ├─ globals.css
│  ├─ product/[id]/page.jsx    상품 상세페이지
│  └─ reservations/page.jsx    예약 검색 페이지
├─ lib/
│  └─ sheet.js                 구글시트 CSV 불러와서 파싱
├─ package.json
└─ .env.local.example
```

## 1단계 — 구글 시트 두 개 준비

### ① 상품마스터 시트

열 순서를 **정확히 이대로** 만들어주세요 (1행은 헤더). 옵션은 최대 8개(`option1`~`option8`,
`price1`~`price8`)까지 쓸 수 있고, 안 쓰는 옵션 칸은 비워두면 됩니다:

| id | date | category | name | status | image | description | shiping fee | option1 | price1 | option2 | price2 | ... |
|----|------|----------|------|--------|-------|-------------|-------------|---------|--------|---------|--------|-----|
| p001 | 2026-08-19 | 수산물 | 완도활전복 1kg | 주문가능 | https://res.cloudinary.com/.../abalone.jpg | 완도산 자연산 전복입니다.<br>당일 수급 당일 발송 | 3000 | 5~6미 | 33400 | 6~7미 | 31600 | ... |

- `id` : 상품마다 고유값 (p001, p002... 그냥 순서대로 적으면 됨)
- `category` : 수산물 / 농산물 / 축산물 / 김치 / 젓갈 / 과일 / 가공식품 중 하나
- `status` : 주문가능 / 품절 / 시즌종료 중 하나
- `description` : 줄바꿈하고 싶은 곳에 `<br>` 넣으면 상세페이지에서 줄바꿈으로 나옵니다
- `shiping fee` : 이 상품 주문 1건당 붙는 배송비(원). 무료배송이면 0. (열 이름 철자 그대로 써야 합니다)
- `option1~8` / `price1~8` : 옵션명과 그 옵션의 가격. 옵션이 하나뿐이어도 `option1`/`price1`에만 채우면 됩니다.
  목록 화면·상세페이지에는 옵션 중 최저가가 "○○원부터"로 표시되고, 주문 화면에서 고객이 옵션을 선택합니다.

### ② 예약기록 시트

| nickname | item | status | date |
|----------|------|--------|------|
| 딸기맘 | 활전복 2미 | 결제완료 | 2026-08-18 |

## 2단계 — 시트를 "웹에 게시(CSV)"로 공개

각 시트에서:
`파일 → 공유 → 웹에 게시 → 시트 선택 → 형식: 쉼표로 구분된 값(.csv) → 게시`

게시하면 나오는 URL을 복사해서 `.env.local`에 넣습니다 (아래 3단계).

> 이 방식은 API 키/인증 설정이 전혀 필요 없어서 가장 빠르고 안정적입니다.
> 시트 자체를 "링크가 있는 모든 사용자에게 공개"로 바꿀 필요는 없습니다 — 웹 게시는 별도 권한입니다.

## 3단계 — 이미지 준비 (Cloudinary)

1. cloudinary.com 무료 가입
2. 대시보드에서 이미지 업로드 (또는 Media Library에 드래그)
3. 업로드된 이미지의 URL 복사 → 상품마스터 시트 `image` 열에 붙여넣기

기존에 카페24/쿠팡에 올려둔 상품 사진 URL이 있다면 그걸 그대로 써도 됩니다.

## 4단계 — 로컬 설정

```bash
cd dandan-shop
npm install
cp .env.local.example .env.local
```

`.env.local`을 열어서 2단계에서 복사한 CSV 게시 URL 두 개를 넣습니다:

```
PRODUCTS_CSV_URL=https://docs.google.com/spreadsheets/d/e/.../pub?output=csv
RESERVATIONS_CSV_URL=https://docs.google.com/spreadsheets/d/e/.../pub?output=csv
```

```bash
npm run dev
```

`http://localhost:3000` 에서 확인.

## 5단계 — Vercel 무료 배포

1. 이 폴더를 GitHub 저장소로 push
2. vercel.com → New Project → 방금 만든 저장소 선택 → Import
3. Environment Variables에 `.env.local`과 똑같이 두 개 추가
4. Deploy 클릭

몇 분 뒤 `단단상회.vercel.app` 형태(또는 랜덤 이름)로 바로 접속 가능. 나중에 실제 도메인 연결도 Vercel 설정에서 무료로 가능합니다.

## 6단계 — 주문/결제(계좌이체) 연동

카드결제 PG 없이 계좌이체 + 수동 확인 방식입니다.
발송인(주문자)과 수취인(받는 분) 정보를 따로 받아서, 선물 발송 같은 경우도 처리할 수 있습니다.

1. **예약기록 시트 헤더를 이렇게 만드세요** (총 18열, 순서 정확히):
   ```
   아이디 | 주문일시 | 발송인 | 발송인 주소 | 발송인 전화번호 | 수취인 | 수취인 전화번호 | 수취인 주소 |
   카테고리 | 구매품목 | 수량 | 구매가격 | 배송비 | 합계금액 | 결제상태 | 발주 상태 | 택배사 | 송장번호
   ```
   - `아이디` / `주문일시` / `결제상태`(입금대기 → 입금확인) / `발주 상태`(입금확인중 → 배송준비중 → 배송중 → 배송완료)는
     아래 Apps Script가 주문이 들어올 때마다 자동으로 채웁니다. 직접 입력할 필요 없어요.
   - `발송인`은 실제 입금하실 분과 동일한 이름으로 받습니다 (입금자명 대조용).
   - `택배사` / `송장번호`는 실제 발송할 때 직접 입력하는 칸입니다 (자동 입력 안 됨).
     입력하면 고객이 "내 주문 확인"에서 바로 조회할 수 있습니다.

2. 예약기록 시트에서 **확장 프로그램 → Apps Script** 열기 → 기본 코드 지우고
   `scripts/AppsScript.gs` 내용을 그대로 붙여넣기 → 저장

3. 오른쪽 위 **배포 → 새 배포** → 유형: **웹 앱** 선택
   - 실행 계정: 나
   - 액세스 권한: **모든 사용자**
   - 배포 클릭 → 권한 승인 → 나온 **웹 앱 URL** 복사

4. `.env.local`에 추가:
   ```
   ORDER_WEBHOOK_URL=(3번에서 복사한 URL)
   NEXT_PUBLIC_BANK_NAME=00은행
   NEXT_PUBLIC_BANK_ACCOUNT=000-0000-0000
   NEXT_PUBLIC_BANK_HOLDER=단단상회
   ```
   배송비는 여기서 설정하지 않습니다 — 1단계 상품마스터 시트의 `shiping fee` 열에서 상품마다 따로 설정하세요.

5. 고객은 상품 상세페이지에서 **"장바구니에 담기"**(여러 상품 동시 주문 가능) 또는 **"바로 주문하기"**(담고 바로 결제)로
   담은 뒤, `/checkout`에서 아래 정보를 한 번만 입력합니다:
   - 발송인(주문자) 성함 / 전화번호 / 주소
   - 수취인(받는 분) 성함 / 전화번호 / 주소 (발송인과 같으면 체크박스로 자동 복사)

   접수되면 예약기록 시트에 **담았던 상품 개수만큼 줄이 자동으로 추가**됩니다 — 모두 같은
   주문번호(`ORD-0001`부터, 상품 여러 개면 그만큼 다음 번호가 듬성듬성 늘어남)를 공유하고,
   발송인/수취인/주문일시/결제상태도 동일하게 채워지되, 카테고리·구매품목·수량·구매가격·배송비·합계금액은
   그 상품 한 줄 기준 값입니다. 결제상태 **"입금대기"**, 발주 상태 **"입금확인중"**으로 시작합니다.

6. 진행 상황에 따라 시트에서 직접 값을 바꿔주세요:
   - 입금 확인되면 **결제상태를 "입금확인"**으로 수정 (같은 주문번호의 모든 줄에 적용해주세요)
   - 상품별로 준비/발송 시점이 다를 수 있으니, **발주 상태는 줄마다 따로** "배송준비중" → "배송중" → "배송완료"로 수정
   - 발송할 때 그 줄의 **택배사·송장번호**를 입력하면 고객이 바로 조회할 수 있습니다

   고객은 "내 주문 확인"에서 **주문번호(아이디) 또는 발송인/수취인 성함**으로 검색해
   (주문번호가 같으면 상품별 줄이 전부 검색됩니다) 결제상태·발주 상태(그리고 입력되어 있으면
   택배사·송장번호)를 볼 수 있습니다 (주소·전화번호 같은 개인정보는 검색 결과 화면에 노출되지 않습니다).

> Apps Script를 수정해서 배포할 때마다(코드 변경 시) "새 배포"가 아니라
> 기존 배포 옆의 **수정(연필 아이콘) → 새 버전**으로 업데이트해야 URL이 안 바뀝니다.

> 예약기록 시트가 "웹에 게시(CSV)"로 공개되어 있으므로(2단계), 개인정보 보호를 위해
> 검색 결과 화면에는 항상 최소한의 정보(주문번호·품목·상태)만 보여주도록 되어 있습니다.
> 시트 원본에는 주소·전화번호가 그대로 남아있으니, 게시 URL이 외부에 유출되지 않도록 주의하세요.

## 7단계 — 로그인 시스템 연동

**주문(체크아웃)할 때만 로그인이 필요합니다** — 상품 목록/상세는 누구나 볼 수 있어요.
전화번호 + 비밀번호로 간단히 가입하고, 로그인은 90일간 유지됩니다(쿠키 기반).

1. **새 구글 시트를 하나 더 만들고 "회원"이라고 이름 붙이세요.** 헤더는 이렇게(총 7열, 순서 정확히):
   ```
   전화번호 | 비밀번호해시 | 가입일시 | 연간주문횟수 | 연간주문금액 | 당월주문량 | 당월주문금액
   ```
   - `비밀번호해시`와 `가입일시`는 자동으로 채워집니다. **절대 평문 비밀번호가 여기 들어가지 않습니다**
     (Next.js 서버가 회원가입 시 미리 해시(scrypt)해서 보냅니다).
   - `연간주문횟수`/`연간주문금액`/`당월주문량`/`당월주문금액`(D~G열)은 가입 시 0으로 시작하고,
     이후 그 전화번호로 주문이 들어올 때마다 **예약기록 시트 쪽 Apps Script가 자동으로 다시 계산**해서
     채워줍니다. 직접 입력/수정할 필요 없어요.

2. 상품마스터/예약기록 시트 때와 똑같이 진행하세요:
   - `파일 → 공유 → 웹에 게시 → CSV` → 나온 URL을 `MEMBERS_CSV_URL`에
   - `확장 프로그램 → Apps Script` 열고 `scripts/MemberSignupAppsScript.gs` 내용 붙여넣기 → 저장
   - `배포 → 새 배포 → 웹 앱`, 액세스 권한 **모든 사용자** → 나온 URL을 `MEMBER_SIGNUP_WEBHOOK_URL`에

3. **회원 통계 자동 갱신 연결** — 예약기록 시트의 Apps Script가 이 "회원" 시트를 찾을 수 있게 딱 한 번만 연결해주세요:
   - "회원" 시트 URL에서 `/d/`와 `/edit` 사이의 긴 문자열(시트 ID)을 복사
   - 예약기록 시트 → 확장 프로그램 → Apps Script 편집기 열기 → 왼쪽 **⚙️ 프로젝트 설정** 클릭
   - **스크립트 속성** → **스크립트 속성 추가** → 속성 이름 `MEMBER_SHEET_ID`, 값에 방금 복사한 시트 ID 입력 → 저장
   - 이 설정을 안 해도 주문 접수 자체는 정상 작동하고, 회원 통계 갱신만 건너뜁니다.

4. `.env.local`에 추가:
   ```
   MEMBERS_CSV_URL=(1번 CSV 게시 URL)
   MEMBER_SIGNUP_WEBHOOK_URL=(2번 웹 앱 URL)
   SESSION_SECRET=(아무 랜덤한 긴 문자열 — 32자 이상 추천, 노출되면 안 됨)
   ```
   `SESSION_SECRET`은 터미널에서 이렇게 만들 수 있어요:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

5. 동작 방식:
   - `/signup`에서 전화번호+비밀번호(4자 이상)로 가입 → 자동 로그인
   - `/login`에서 로그인 → 90일간 로그인 유지 (쿠키 만료 전까진 재로그인 불필요)
   - 로그인 안 하고 `/checkout` 접근 시 자동으로 `/login`으로 이동, 로그인 후 다시 체크아웃으로 복귀
   - 주문서의 "발송인 전화번호"는 항상 로그인된 계정 번호로 고정됩니다 (수동 입력 불가, 위조 방지)
   - "내 주문 확인"에서 로그인 상태면 검색 없이 **본인 전화번호로 걸린 주문이 자동으로** 보입니다
     (다른 주문번호/성함으로 검색도 계속 가능합니다)

> Vercel에 배포할 때 Environment Variables에 `MEMBERS_CSV_URL`, `MEMBER_SIGNUP_WEBHOOK_URL`,
> `SESSION_SECRET` 세 개도 반드시 추가해주세요. `SESSION_SECRET`은 로컬과 다른 값을 새로 만들어도 됩니다.

## 데이터 갱신 주기

메인 페이지는 60초마다 자동으로 최신 시트 내용을 다시 불러옵니다 (`revalidate: 60`).
시트에 상품 추가 → 최대 1분 안에 사이트에 반영됩니다. 더 즉시 반영이 필요하면
Google Apps Script로 Vercel의 On-Demand Revalidation을 호출하는 방법도 있는데,
필요하시면 다음 단계로 추가해드릴게요.
